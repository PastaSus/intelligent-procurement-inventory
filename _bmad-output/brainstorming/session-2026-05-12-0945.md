## Phase 1: Expansive Exploration — Cross-Pollination

Explored 4 domains across 2 sessions. Key decisions made:

### Domain A — Chat UI Positioning
- Floating bubble + full-screen route (dual presence)
- Bubble shows notification badge when AI detects something (low stock, reorder suggestion)
- Full-screen has conversation history, search past chats, command palette (Ctrl+K)
- Streaming indicator when AI is thinking
- Suggested prompts below input ("What should I reorder?", "Show low stock")
- Markdown rendering in AI responses, copy button, thumbs up/down feedback

**Final decision: Floating bubble + full-screen route.**
- Bubble = notification center (lightweight, ambient)
- Full-screen = full chat app (when user needs to dig in)
- Works on mobile AND desktop
- Bubble can minimize, expand to full-screen when clicked

### Domain B — AI Suggestions & Human-in-the-Loop
- Shopify AI approach: rich suggestion cards
- Item name, quantity, reasoning ("Sold 30 last month"), confidence level (low/medium/high)
- "Create PO" button pre-fills vendor + line items
- Human edits quantities before saving — not just approve, actual modification

**Final decision: Rich cards + human edits before save.**

### Domain C — Prompt & Data Context
- Option 2: Fetch relevant data only (not full DB)
- Plain text prompt format (no JSON)
- Smart filter for large inventories (>500 items)
- Context budget: send only 50 most relevant items, summarize by category for vague queries

**Final decision: Option 2 — fetch relevant only with smart filtering.**

### Domain D — Fallback & Error UX
- Friendly message: "AI is currently not available, here's your current status instead"
- Show dashboard stats as fallback (low stock count, recent POs)
- Retry button with countdown timer
- Log AI failures for debugging
- Subtle "AI degraded" indicator on bubble

**Rate limiting UX:**
- Visible request counter near chat input ("5/10 requests used")
- Warning when approaching limit
- Countdown timer when hit limit
- "Need more? Contact admin" after 3 failed attempts

**Final decision: Friendly fallback + visible rate limit counter with countdown.**

## Phase 3: SCAMPER — Idea Refinement

### Idea 1: Floating Bubble + Full-Screen Route

**Substitute:** What if bubble was a sticky bottom bar instead of a floating circle?
**Combine:** What if the bubble combined with toast notifications? (AI shows toast, click opens full chat)
**Adapt:** What if the bubble worked as a widget that could be dragged to any corner?
**Modify:** What if bubble showed a live preview of the last AI response? (not just badge)
**Put to other uses:** What if the bubble was also a quick-search for inventory? (type without opening full screen)
**Eliminate:** What if we skip the full-screen and everything happens in the bubble? (simpler, less pages)
**Reverse:** What if AI chat was the main page and dashboard was inside it?

**Decision: Stick with floating bubble + full-screen. Bubble as-is but add notification badge and live preview.**

### Idea 2: Rich Suggestion Cards

**Substitute:** What if instead of cards, suggestions appeared as inline text with action buttons?
**Combine:** What if cards combined with quick stats? (show item + qty + current stock level)
**Adapt:** What if cards adapted based on urgency? (critical = red border, normal = standard)
**Modify:** What if we added a "confidence meter" bar inside the card?
**Put to other uses:** What if cards could also show vendor info? (which supplier to order from)
**Eliminate:** What if we just showed text suggestions without cards? (simpler, less UI)
**Reverse:** What if user had to "dismiss" good suggestions? (instead of accept, dismiss bad ones)

**Decision: Keep rich cards. Add confidence bar, urgency styling, vendor info.**

### Idea 3: Data & Prompt Strategy

**Substitute:** What if we sent full DB summary instead of filtered?
**Combine:** What if we combined context + chat history for smarter answers?
**Adapt:** What if prompts adapted based on query type? (summary vs detail)
**Modify:** What if we cached responses for common queries? (faster, cheaper)
**Put to other uses:** What if context was also used for dashboard, not just chat?
**Eliminate:** What if we removed context and let AI work on metadata only? (risky, not recommended)
**Reverse:** What if user had to manually select which items to include in context? (too much friction)

**Decision: Keep option 2. Add prompt caching for common queries as optimization.**

### Idea 4: Fallback & Rate Limit UX

**Substitute:** What if fallback showed an "AI health" page instead of dashboard?
**Combine:** What if rate limit counter combined with usage tips? ("Tip: Ask one question at a time")
**Adapt:** What if fallback adapted to time of day? (day = stats, night = "AI resting")
**Modify:** What if we showed an "AI usage history" graph to help users understand patterns?
**Put to other uses:** What if rate limit data was also used for analytics? (understand usage patterns)
**Eliminate:** What if we silently dropped requests when rate limited? (bad UX, not recommended)
**Reverse:** What if we gave bonus requests for "good behavior"? (positive reinforcement)

**Decision: Keep fallback + stats. Add usage tips and simple AI health indicator.**

## Phase 4: Decision Tree Mapping

### Decision Tree 1: AI Chat Entry Points

```
User opens AI chat
├── Via notification badge (passive)
│   └── Low stock detected → Badge pulses → Click → Full-screen with suggestion loaded
├── Via floating bubble click (active)
│   └── Bubble expands to full-screen OR opens full-screen route
└── Via command palette (power user)
    └── Ctrl+K → Type query → Results shown inline
```

### Decision Tree 2: AI Suggestion Flow

```
AI generates suggestion
├── User sees rich card
│   ├── Click "Create PO" → Pre-filled PO form → User edits → Save (human-in-the-loop)
│   ├── Click "Edit" → Modify qty/items → "Create PO" → Save
│   └── Dismiss → Card disappears, logged for feedback
└── AI confidence < 50%
    └── Show warning: "This suggestion has low confidence, review carefully"
```

### Decision Tree 3: Error & Rate Limit Flow

```
User sends AI request
├── Request counter: requestsUsed < 9
│   └── Send request → Show loading → Response displayed
├── Request counter: requestsUsed >= 9 (approaching limit)
│   └── Show warning: "9/10 requests used, 1 remaining"
│       └── User confirms → Send request
└── Request counter: requestsUsed >= 10 (rate limited)
    └── Disable input → Show countdown timer
        └── Timer ends → Re-enable input → Counter resets
```

### Decision Tree 4: Fallback Flow

```
AI request fails (timeout, API error, service down)
├── AI service error
│   └── Show: "AI is currently not available, here's your current status"
│       └── Display dashboard stats (low stock, recent POs)
│           └── Show "Retry" button with countdown
└── Network error
    └── Show: "Connection issue, check your internet"
        └── Show "Retry" button

AI service returns degraded response
└── Show subtle "AI degraded" indicator on bubble
    └── When user opens chat, show note: "AI responses may be limited"
```
